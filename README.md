# 台股自動投資策略系統

回測模擬 + 每週操作決策 + 儀表板。

> ⚠️ **這是模擬（paper trading）工具，不是投資建議，也沒有接任何券商。**
> 回測結果來自單一市場、不到兩年的資料，樣本涵蓋的區間幾乎全是多頭；
> 任何「年化 XX%」都不該被當成對未來的預期。

## 安裝

只需要 Python 3 標準函式庫（`sqlite3` / `json` / `gzip` / `math`），沒有第三方套件。

```bash
cp config.example.sh config.sh   # 填入本機路徑與發布目標
```

`config.sh` 不進版控，裡面只有「這台機器在哪、儀表板發到哪」，沒有任何策略邏輯。

## 資料從哪來

執行環境沒有對外網路，但作業者的 Windows PC 有，所以所有外部抓取都走
`pc-operation` bridge 在 PC 上執行，再把檔案拉回來處理。**這是整個系統最大的平台相依性**
（細節見 `HANDOFF/04_MIGRATION_PLAN.md` §2）。資料本身全部是 TWSE / 集保的公開資料。

| 來源 | 內容 | 用途 |
|---|---|---|
| TWSE `MI_INDEX` | 每日全上市 OHLCV / 成交值 | 價格、動能、流動性 |
| TWSE `T86` | 三大法人買賣超 | **籌碼**：外資、投信、自營 |
| TWSE `MI_MARGN` | 融資融券餘額 | **籌碼**：散戶槓桿 |
| TWSE `TWT49U` | 除權息計算結果 | 還原股價（關鍵，見下） |
| cnyes / Yahoo RSS | 財經新聞 | 資訊面板（不進訊號） |

## 策略邏輯

> ⚠️ **本節自 2026-08-19 起未同步更新**（停損已放寬、改為 conviction 加權與零股成交、
> 加入階梯式進出與風險調整動能等）。與 `HANDOFF/03_DECISION_LOG.md` 衝突時，**以 decision log 為準**。

**選股池**：上市普通股（1101–9999）、股價 ≥ NT$10、20 日成交值中位數 ≥ NT$5,000 萬、
收盤價站上 MA60。

**綜合分數**（各項先做橫斷面 z-score，截尾 ±3）：

| 權重 | 訊號 | 說明 |
|---|---|---|
| +0.35 | 60 日動能（跳過最近 5 日） | 跳過近期是為了避開短期反轉 |
| +0.30 | 外資 20 日淨買 ÷ 20 日成交值 | 用成交值標準化，大小型股才可比 |
| +0.25 | 投信 10 日淨買 ÷ 10 日成交值 | 投信在台股是較短線但有效的籌碼訊號 |
| −0.10 | 融資餘額 20 日增幅 | 散戶槓桿堆高 = 籌碼凌亂，扣分 |

**每週操作**：週五收盤後算分 → **下週一開盤**成交。取分數前 **6 名**等權重，
設 15% 不交易區間避免無謂周轉。

**部位數 (top_n=6，Sam 2026-08-17 指定 3–6 檔)**：選 6 而不是 3，理由是穩健度不是報酬。
把選股名次視窗往後挪一名（同樣任意的選擇）：3 檔版本從 **+87.2% 變成 −12.8%**（全距 100pp），
6 檔版本 49.6% / 23.9% / 50.4%（全距 26pp）。3 檔那個漂亮數字是運氣，不是策略。

**零股單位 (lot_size=100，Sam 2026-08-17)**：一單位必須放得進單檔預算 →
**可買股價上限 = 單檔預算 ÷ 100**（6 檔時 NT$1,667）。超過的個股直接不進選股池 ——
這是可交易性限制，跟流動性門檻同一類，不是報酬調參。
`max_weight` 改為由 `top_n` 推導（`eff_max_w()`），否則固定 20% 上限在少於 5 檔時會鎖死資金。

**市場水位**（以 0050 為代理）：站上 MA60 且 MA200 → 100%；跌破 MA60 → 70%；
跌破 MA200 → 40%。

**緊急操作（每日檢查，不是只有週檢）**：
- 個股停損 −8%（自成本）
- 移動停損 −12%（自持有期最高點）
- 大盤單日 −3.5%，或組合回撤 −12% → **全數出清**，且在市場回到 risk-on 前不進場
- 被停損的個股冷卻 10 個交易日，避免立刻買回去被巴第二次

## 方法上的三個地雷（已處理）

1. **除權息**：TWSE 收盤價**未還原**，台股 7–9 月除權息集中期正好在回測區間內。
   不還原的話，配息 4% 會被當成單日下跌 4%，同時低估報酬又觸發根本不存在的停損。
   已用 `TWT49U` 建立回溯還原因子。
2. **未來函數**：所有決策只用 D 日（含）以前資料，一律 D+1 **開盤**成交。
   緊急出場也是當天發現、隔天開盤賣 —— 不是用當天最低點回測。
3. **倖存者偏誤**：universe 由每天實際有交易的個股重建，下市股在下市前都還在樣本內。

## 已知限制

- **1 年、約 50 次決策，樣本太小**，不足以區分「有效」與「運氣」。
- 參數是事前寫定、沒有回頭最佳化 —— 降低過度配適，但不代表是最佳參數。
- 未模擬：漲跌停鎖死、處置股分盤、停牌、股利稅負（含二代健保）、借券成本。
- 以零股成交假設（1M 分 8 檔，單檔 12.5 萬，高價股一張就超過）。盤中零股價差較大，
  已用 0.1% 滑價涵蓋，極端情況可能不足。
- **停損為「D 日收盤判定、D+1 開盤成交」，非即時停損**：實例 7610（2026-08-18買
  2026-08-19停損賣出），收盤觸發時 −9.6%，隔日開盤跳空又跌，實際成交 −15.15%
  （虧損NT$6,357，約當日總資產0.64%）。0.1%滑價參數涵蓋的是價差/衝擊成本，不是
  隔夜跳空——這是日K引擎的結構性限制，不是bug；若未來接真實券商，intraday的
  stop-limit單可即時成交，不會有這個放大效果。n=1，僅記錄機制，非結論。
- 新聞**不進回測訊號** —— 歷史新聞難以對齊「當時可得」時點，硬做情緒分數會嚴重灌水。

## 模擬帳戶 (Paper Trading)

`paper.py` 用**和回測完全相同的 Engine** 逐日推進 — 兩邊共用一份決策程式碼，
不會出現「回測的策略」和「實際在跑的策略」悄悄分岔的情況。狀態存在
`paper_state.json`，**以日期為 key**（不是 session index），所以之後往前補歷史
資料也不會把 cooldown / halt 狀態錯位。

```bash
python3 paper.py init --capital 1000000   # 開戶，並掛出下一個交易日的委託
python3 paper.py step                     # 有新交易日資料時推進
python3 paper.py orders                   # 列出下一個開盤要送的單
python3 paper.py report                   # 產生 paper_result.json
./run_daily_paper.sh                      # 每日全自動（已排程 20:00 台北時間，週一~五）
```

**時序**：D 日收盤後決策 → **D+1 開盤成交**。和回測同一條規則，沒有未來函數。
開戶當天用 `force=True` 略過「只在週五換股」的節奏，之後回到每週換股 +
每日緊急檢查的正常循環。

`run_daily_paper.sh` **fail-closed**：PC bridge 不通、或資料筆數不足，就直接結束、
不動 `paper_state.json`、不重新發佈。寧可停在昨天的正確狀態，也不要用半套資料推進。

## 未來函數防護（Sam 同意，2026-08-17）

兩層，一便宜一貴：

**1. 結構不變量（每一筆成交都檢查，零成本）** — `Engine._fill()` 斷言
「成交日必須嚴格晚於決策日」。同根K棒成交是最容易在重構時不小心加回來的偏誤
（一次把 `rebalance()` 和 `_fill()` 用同一個 index 呼叫就成立），而且**這種偏誤看報酬
是看不出來的**。已驗證：強制同日成交會拋出 `LOOK-AHEAD: fill on ... from a decision
made on ...`。

**2. 未來函數哨兵 `sentinel.py`（strategy.py 有變動、或每週五才跑）** —
跑一個明知作弊的版本（用**明天**的資料選股），要求誠實版與它保持距離。
資料洩漏沒辦法用「報酬好不好」判斷，因為洩漏的回測就是會好看；但它**沒辦法
離作弊版很遠**。門檻：報酬或 Sharpe 超過作弊版的 50% 就告警。

已做故障注入驗證（不是只看它跑得過）：

| 狀態 | 誠實版報酬 | 比值 | 結果 | exit |
|---|---|---|---|---|
| 正常 | +49.6% | 4.8% | CLEAN | 0 |
| 故意植入洩漏（用明日價算動能） | +675.1% | **64.8%** | **SUSPICIOUS** | **1** |
| strategy.py 未變動、非週五 | — | — | skipped | 0 |

`run_daily_paper.sh` 在 `paper.py step` **之前**擋：哨兵失敗就**不推進帳戶、不重新發佈**，
只寫 log。理由同 CMT dashboard 的教訓 —— 停在昨天的正確狀態，好過用有問題的引擎前進。

`lookahead_demo.py` 保留四種未來函數的完整示範（同K棒 / 完美日內擇時 / 明日排名 /
完美預知），改策略後可當回歸測試重跑。
